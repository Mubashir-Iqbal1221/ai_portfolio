Safety alerts on edge devices, and an agent to question them

A facility has many cameras and few people watching them. We delivered the first version of a system that watches camera feeds on an edge device, flags violence, falls and intrusions, and lets operators ask about any event in plain words, by voice or text.

At a glance

  • Client: a secure facility
  • Scope: first version, delivered and deployed
  • My role: built the operator agent over the event database, configured the Jetson and its network access, and helped shape the vision pipeline's design
  • Result: 4 camera streams, stable at 2 fps each, in a throughput benchmark on the Jetson
  • Stack: NVIDIA Jetson, DeepStream, YOLOv8, Google ADK, Gemini, LiteLLM, MCP Toolbox, PostgreSQL, Tailscale, Docker

The problem

A fight or a fall needs a response within moments, but running a large model on every frame of every camera is too slow and too costly for a device on site. Once an event is flagged, operators also need answers fast, without scrubbing through footage or writing SQL.

What we built

  • A funnel from cheap checks to costly ones. Each camera is sampled down to a few frames per second. Quick checks catch camera tampering, frames with nobody in them stop at person detection, and pose and motion give each frame an anomaly score. Only high-scoring frames go to a vision-language model, so most frames never reach the costly step.
  • Detection on the Jetson. We run YOLOv8 inside an NVIDIA DeepStream pipeline on the device. Each event saves a clip from 5 seconds before to 5 seconds after, as evidence.
  • An agent operators can question. I built the agent operators use to ask questions such as how many falls happened at a site this week. It answers by text or voice, draws charts, and writes an incident report for each event.
  • Open questions, without open access. Operators ask questions nobody can list in advance, so a fixed set of predefined queries would not cover them, and the agent writes its own SQL. To keep that safe without relying on the prompt, I created a database user with only the access we chose to expose, and the agent's database toolbox connects through that user alone. Row-level security then limits every query to the user's own organisation and sites.
  • Sessions that pick up where they left off. Conversations are saved, and a voice session resumes from a cleaned, trimmed history, so old audio and tool output cannot confuse the model.
  • The device, connected. I configured the Jetson, connected its services, and set up secure network access to it with Tailscale.
