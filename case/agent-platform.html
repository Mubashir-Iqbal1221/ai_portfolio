Case study · 2026

Agents under each organisation's control

Agents are only useful if they can act in a company's own tools, such as Slack, Gmail, OneDrive or a database, and companies only allow that if they stay in control. This platform serves many organisations at once, and each one decides who can use which tools and which words its people should never type.

At a glance

  • Product: a workflow automation platform for many organisations at once
  • My role: built the agents, their memory and orchestration, the MCP tools, role-based access to those tools, live content checks per organisation, and the Keycloak sign-in setup
  • Stack: Python, OpenAI Agents SDK, MCP, Keycloak, Presidio, WebSockets

The problem

Companies want agents that can act through the tools they already use. Before they let one in, they need control: who may use which tool, what must never leave the company, and what their people should not type. On a platform shared by many organisations, each one needs that control over its own users, without affecting anyone else. And every connected tool adds to the model's context, so with many tools connected, most of that space goes to tools the task never uses.

What I built and decided

  • The agents, their memory and orchestration. I built the agents that plan a task, call the right tools and keep track of the conversation.
  • Tools, with access by role. I built the MCP servers that connect each tool, and each role sees only the tools it is allowed to use. Users add or remove tools as they need them, within those limits.
  • Live checks, set per organisation. As a user types, a checker flags profanity on the spot. Each organisation adds its own blocked words, such as internal code names, and the list applies only to its own users.
  • Sign-in and roles. I set up Keycloak for sign-in and roles across the platform.
  • Tools loaded only when picked. We made agents discover the connected tools at runtime and load only the ones a task needs, which keeps the context small.
  • Safety layers. We added guardrails, masking of personal data with Presidio before it reaches the model, and a fact-checker that flags contradictions between sources instead of hiding them.
